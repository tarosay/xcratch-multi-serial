## 1. Web Serial API による制約

ブラウザの仕様で決まっていて、拡張機能の作りでは避けられない。ブロックの形はここから決まる。

### ポートを COM 名で指定できない

`SerialPort.getInfo()` が返すのは `usbVendorId` / `usbProductId` /
`bluetoothServiceClassId` だけで、**COM 名もシリアル番号も取れない。**
ポートはブラウザの選択ダイアログで利用者が選ぶ。

そこで拡張機能の中では、選ばれたポートを **「シリアル通信 1」〜「シリアル通信 8」の番号**に
割り当てて区別する。**この番号は COM の番号とは関係ない。** どの COM を何番にするかは、
ダイアログでどれを選んだかだけで決まる。

ブロックの呼び名を「ポート」にしなかったのは、COM ポートの番号と取り違えやすいため。

### ダイアログは利用者の操作からしか出せない

`navigator.serial.requestPort()` は transient activation（利用者の操作の直後）を要求する。

この拡張機能では、次の 2 つの経路でダイアログが出ることを Xcratch の実機で確認済み（2026-10-13）。

- **「開始する」ブロックのクリック**
- **緑の旗のクリック**（`緑の旗が押されたとき` の直後に「開始する」を置いた場合）

緑の旗も利用者のクリックなので、ブラウザはその直後とみなす。
書き起こしの時点では「緑の旗からは失敗する」と書いていたが（お手本の WebHID のコメントに
基づく推測で、確かめていなかった）、実機では出た。

**1 回のクリックで出せるダイアログは 1 つだけ**（実機で確認、2026-10-13）。
`緑の旗が押されたとき` の下に「開始する」を 2 つ続けて置くと、1 つ目のダイアログしか出ない。
1 つ目でクリックの権利を使い切るのか、選んでいる間に時間切れになるのかは区別できていないが、
どちらにしても 2 つ目は当てにできない。

**操作から時間が経ってから「開始する」が動いても失敗する。** たとえば「〇秒待つ」の後。
どれだけ経つと失敗するかはブラウザが決めることで、ここでは確かめていない。

### ダイアログを出せなかったら、次のクリックを待つ

この拡張機能は複数台をつなぐのが目的なので、上の制約のままでは使いにくい
（2 台目以降を 1 つずつブロックのクリックで始めることになる）。そこで（打ち合わせで決定、2026-10-13）:

- ダイアログを出せなかった「開始する」は、**そこで止まって待つ。** 状態は「画面をクリックしてください」
- **画面のどこかをクリックすると、待っている「開始する」のダイアログが出る**
- 待っているものが複数あれば、1 クリックにつき 1 つずつ、待ち始めた順に出す
- 止めるボタンを押すと待つのをやめる。状態は「開始していません」に戻る

`緑の旗が押されたとき` の下に「開始する」を 2 つ置いた場合の流れは
「旗 → 1 つ目のダイアログで選ぶ → 画面をクリック → 2 つ目のダイアログで選ぶ」になる。

**1 回のクリックにつき、ダイアログは 1 回しか出そうとしない。** 2 つ目以降の「開始する」は
`requestPort()` を呼ばずに、すぐ「画面をクリックしてください」で待つ。
最初の作りでは 2 つ目でも `requestPort()` を呼び、失敗（SecurityError）したら待つようにしていたが、
実機では 1 つ目のダイアログを閉じた直後に呼ぶと失敗の仕方が当てにならなかった（2026-10-13）。

- 1 つ目をすぐ選ぶと、2 つ目は NotFoundError（キャンセルと同じ）で返り、「選ばれませんでした」になった
- 1 つ目を 10 秒ほど待ってから選ぶと、2 つ目は 1 つ目と同じポートで返り、「ほかの番号で使っています」になった。
  なぜ同じポートが返るのかは分かっていない

Chrome は、クリックの直後でなければ SecurityError を返す（Blink の `serial.cc`、
`HasTransientUserActivation` を見ている）。上の 2 つはそれに当たらない動きで、
ダイアログを続けて出すこと自体を避けるのが確実と判断した。

「クリックがあったか」は、`window` の `click`（capture）で覚えておき、「開始する」が
ダイアログを出すたびに使い切る。緑の旗や「開始する」ブロックのクリックも、この `click` で拾える。

⚠ クリックは `window` の `click` を capture で拾い、`setTimeout(0)` で一拍おいてから
ダイアログを出す。止めるボタンのクリックで待ちを取り消す処理（`PROJECT_STOP_ALL`）を先に
済ませるため。ダイアログは操作の直後なら出せるので、一拍おいても間に合う。

この仕組みで、画面のクリックから 2 つ目のダイアログが出ることを実機で確認した（2026-10-13）。

### ステータスボタン「！」と接続モーダルは使わない

**開始はブロックだけで行う（打ち合わせで決定）。** `getInfo()` に `showStatusButton` を立てず、
entry の `launchPeripheralConnectionFlow` も `false` にする。

「！」は拡張機能ごとに 1 つしか無く、つなぐと「接続済み」に変わるので、8 つの番号を扱えない。
使うとすれば「1 台目だけ『！』、2 台目以降はブロック」になり、開始の仕方が 2 通りになる。
「接続済み」と出ていても全部がつながっているとは限らず、**利用者を困惑させる**ため出さない。

### 読み込み直すと閉じる

ページを読み込み直すとポートは閉じる。開始し直す必要がある。

前回許可したポートは `navigator.serial.getPorts()` で拾えるので、自動でつなぎ直すことも
技術的にはできる。ただし、シリアル番号が取れないため、**どの機器が何番になるかを保証できない。**
初版には入れない。

### ダイアログで機器を絞り込まない

`requestPort()` に `filters` を渡さない。すべてのシリアルポートがダイアログに出る。
汎用にするため（打ち合わせで決定）。

将来 VID/PID で絞り込む必要が出ても、絞り込みはダイアログに出す候補を選ぶだけなので、
**作品やブロックの形に影響しない。** 後から足せる。

## 2. ブロック

`(1▼)` は数値を入れられるメニュー（`acceptReporters: true`）、
`[1▼]` は選ぶだけのメニュー（`acceptReporters: false`）。

### 開始・終了

| opcode | 文言（`ja`） | 種類 |
|---|---|---|
| `openChannel` | シリアル通信 (1▼) を ボーレート (115200▼) で開始する | 命令 |
| `closeChannel` | シリアル通信 (1▼) を終了する | 命令 |
| `isOpen` | シリアル通信 (1▼) は開始されている | 真偽 |
| `channelState` | シリアル通信 (1▼) の状態 | 値 |

「接続する」「切断する」ではなく「開始する」「終了する」にしたのは、
「通信を接続する」が日本語として不自然なため。お手本の
`シリアル通信 ボーレート [ ] で開始する` とも揃う。

### 受信

| opcode | 文言（`ja`） | 種類 |
|---|---|---|
| `whenReceived` | シリアル通信 [1▼] で受け取ったとき | ハット |
| `readLine` | シリアル通信 (1▼) から1行読む | 値 |
| `latestLine` | シリアル通信 (1▼) の最新の行 | 値 |
| `namedValue` | シリアル通信 (1▼) の [x] の値 | 値 |
| `hasData` | シリアル通信 (1▼) に受信データがある | 真偽 |
| `clearData` | シリアル通信 (1▼) の受信データを捨てる | 命令 |
| `setLineDelimiter` | シリアル通信 (1▼) の行の区切りを [改行▼] にする | 命令 |

### 取り出し（シリアル通信の番号を持たない。文字列だけを扱う）

| opcode | 文言（`ja`） | 種類 | 例 |
|---|---|---|---|
| `itemOf` | (12,34,56) を [カンマ▼] で区切った (2) 番目 | 値 | → `34` |
| `itemCount` | (12,34,56) を [カンマ▼] で区切った項目の数 | 値 | → `3` |
| `numberIn` | (temp=23.5) の中の数値 | 値 | → `23.5` |
| `splitToList` | (12,34,56) を [カンマ▼] で区切ってリスト [▼] に入れる | 命令 | |

### 引数

| 引数 | メニュー | 既定値 | 備考 |
|---|---|---|---|
| 番号 | `1`〜`8` | `1` | ハットだけ `acceptReporters: false`（「6. ハットブロック」） |
| ボーレート | 1200 / 2400 / 4800 / 9600 / 19200 / 38400 / 57600 / 115200 | `115200` | 変数から任意の値も渡せる |
| 行の区切り | 改行 / カンマ / タブ / スペース / セミコロン | 改行 | 任意の文字も入れられる |
| 項目の区切り | カンマ / スペース / タブ / コロン / セミコロン | カンマ | 任意の文字も入れられる |
| 名前 | （文字の入力欄） | `x` | |
| リスト | 作品にあるリストの一覧 | | お手本の `getListItems()` と同じ作り |

**ボーレートの既定値 115200 は MakeCode（micro:bit）の既定値。**
MakeCode のリファレンス（`serial.setBaudRate`）にも、既定値は 115200 と書かれている。

**番号は、変数から渡すブロックでも 1〜8 に揃える。** ハットブロックは 1〜8 しか選べないので、
ほかのブロックだけ 9 以上を受け付けると、使える番号がブロックによって違ってしまう。
範囲外の番号を渡されたときは何もせず、値のブロックは空文字（真偽は `false`）を返す。

## 3. 開始・終了の動き

### `openChannel`

1. その番号が **受信中なら何もしない**（下の「受信中の番号で開始したとき」）
2. Web Serial API が無ければ、状態を「このブラウザでは使えません」にして終わる
3. `requestPort()`（`filters` なし）でダイアログを出す
   - 選ばれなかった → 状態「選ばれませんでした」
   - 前のクリックをほかの「開始する」が使った、または利用者の操作の直後でない →
     状態「画面をクリックしてください」で待つ。
     クリックされたら、この手順 3 からやり直す（「1. Web Serial API による制約」の
     「ダイアログを出せなかったら、次のクリックを待つ」）
4. 選ばれたポートが **ほかの番号で開いている**なら断る。状態「ほかの番号で使っています」
5. `port.open()` で開く。設定は 8 ビット・パリティなし・ストップビット 1・フロー制御なし
   - 失敗 → 状態「開けませんでした」。ほかのアプリ（MakeCode やシリアルモニタなど）が
     使っていると、ここで失敗する
6. 状態「受信中」。受信のループを回し始める

### 受信中の番号で開始したとき

**何もしない**（打ち合わせで決定、2026-10-13）。ダイアログも出さない。

`受け取ったとき` や `ずっと` の中に「開始する」を置くと、くり返し開始が呼ばれる。
何かするようにしておくと、クリックのたびにダイアログが出て使えなくなる（実機で起きた、2026-10-13）。

**ボーレートを変えるには、先に「終了する」を動かしてから「開始する」。**

当初は「受信中でも毎回ダイアログを出し、選び直したら開き直す（キャンセルなら受信を続ける）」と
していたが、上の理由でやめた。

### `closeChannel`

受信のループを止めてポートを閉じる。状態「開始していません」。
受信済みのデータは残す（「1行読む」で読める）。

### ケーブルを抜いたとき

`navigator.serial` の `disconnect` イベント、または読み出しの失敗で検出する。
状態「切れました」。`isOpen` は `false` になる。

### 止めるボタン（赤い八角形）

**通信は閉じない。** 止めるボタンはスクリプトを止めるもので、つながりを切るものではない。

### `channelState` の値

画面の言語（`ja` / `ja-Hira` / `en`）で返す。開発者コンソールを見ない利用者に、
うまくいかない理由を見せるためのブロック。

文言は書き起こしで提案し、打ち合わせで了承された。

| 状態 | `ja` | `ja-Hira` | `en` |
|---|---|---|---|
| 未開始 | 開始していません | かいし していません | not started |
| 選択中 | ポートを選んでいます | ポートを えらんでいます | choosing a port |
| 受信中 | 受信中 | じゅしんちゅう | receiving |
| 取り消し | 選ばれませんでした | えらばれませんでした | no port was chosen |
| クリックが要る | 画面をクリックしてください | がめんを クリックして ください | click anywhere on the page |
| 重複 | ほかの番号で使っています | ほかの ばんごうで つかっています | in use by another number |
| 開けない | 開けませんでした | ひらけませんでした | could not open the port |
| 抜けた | 切れました | きれました | disconnected |
| 非対応 | このブラウザでは使えません | このブラウザでは つかえません | not supported in this browser |

「クリックが要る」の文言は、当初の「ブロックをクリックしてください」から変えた（2026-10-13）。
画面のどこをクリックしてもダイアログが出る作りにしたため。

## 4. 受信の作り

番号ごとに次のものを持つ。

| 持つもの | 中身 |
|---|---|
| 途中の文字列 | まだ行の区切りが来ていない文字列 |
| 行の列 | 区切り終わった行。古い順。「1行読む」はここから取り出す |
| 最新の行 | 最後に区切り終わった行。「最新の行」はこれを返す |
| 名前と値の表 | 「名前:値」の形の行から作る。「[x] の値」はこれを引く |
| 行の区切り | 既定は改行 |

### 文字コード

`TextDecoder('utf-8', {stream: true})` で、届いた順に文字へ戻す。
**日本語などの文字が受信の切れ目で 2 回に分かれても、文字化けしない。**

### 改行の扱い

区切りが「改行」のときは LF・CR・CR+LF のどれも 1 つの行の終わりとみなす。
送り手によって違うため（MakeCode の `serial.writeLine` は CR+LF）。

### 開始した直後の 1 行は捨てる

相手が送っている途中に開始すると、最初の行は途中から始まり、壊れた値になるため。

捨てるのは「開始してから、**行の区切り**（`setLineDelimiter` で決めたもの。既定は改行）が
最初に来るまで」の文字列。区切りをカンマにしていれば、最初のカンマまでを捨てる。
受信のブロックはどれも区切り終わった行を扱うので、捨てた分はどのブロックにも出てこない。

相手がまだ何も送っていない状態で開始した場合は、正しい最初の行を 1 つ失う。
受信のみの通信では、どちらの場合かを見分ける手段がない。それでも捨てる（打ち合わせで決定）。

捨てるのは `openChannel` で開いた直後だけ。「受信データを捨てる」や区切りの変更では捨てない。

### 溜まりすぎたら古い方から捨てる

| 対象 | 上限 |
|---|---|
| 行の列 | 1000 行 |
| 途中の文字列（区切りが来ないまま） | 4096 文字 |

上限に達したら**古い方から捨てる。** 新しい方を捨てると、ずっと前のデータを
読み続けることになって気付きにくい（お手本と同じ方針）。

上限の数値は書き起こしで提案し、打ち合わせで了承された。

### 「最新の行」

読んでも消えない。次の行が届くまで同じ値を返す。

micro:bit がセンサーの値を送り続けると、「1行読む」では古い行から順に読むことになり、
読む速さが追いつかないと表示が遅れていく。今の値だけが欲しい用途ではこちらを使う。

### 「[x] の値」

MakeCode の `serial.writeValue("x", 123)` が送る `x:123` の形の行を読む
（MakeCode のリファレンスで `name:value` と `\r\n` を送ると確認済み）。
行が届くたびに、`:` で分けて名前と値の表を更新する。

次の扱いは書き起こしで提案し、打ち合わせで了承された。

- `=` で区切った行（`x=123`）も同じに扱う。Arduino などでよく使われる書き方のため。
  最初に現れた `:` か `=` で分ける
- 名前と値の前後の空白は除く（`x = 5` も読めるように）。**大文字と小文字は区別しない**（Scratch の「=」と同じ）
- まだ届いていない名前は空文字を返す
- 1 行に 1 組だけ読む（`x:1,y:2` のような行は扱わない）

### 「受信データを捨てる」

行の列・途中の文字列・最新の行・名前と値の表をすべて空にする。

### 行の区切りを変えたとき

それより後に区切る分から新しい区切りを使う。区切り終わった行はそのまま。

## 5. 取り出しの作り

| ブロック | 決め事 |
|---|---|
| `itemOf` | 番号は 1 から。範囲外は空文字。各項目の前後の空白は除く |
| `itemCount` | 空の文字列は 0 |
| `numberIn` | 最初に現れる数値（符号・小数点を含む）。無ければ空文字 |
| `splitToList` | リストの中身を置き換える |

区切りが「スペース」のときは、続いた空白を 1 つとみなす（書き起こしで提案し、打ち合わせで了承）。
それ以外の区切りでは空の項目も 1 つと数える（`1,,3` は 3 項目）。

## 6. ハットブロック（`whenReceived`）

お手本の `whenSerialReceived` と同じ作り。

- `isEdgeActivated: false`。VM は毎フレーム見に来ない
- 33ms ごとのタイマーで、**読まれていない行がある番号**のハットを `runtime.startHats()` で起こす
- 同じハットのスクリプトがまだ動いていれば、`startHats()` は起こし直さない

⚠ 番号のメニューは `acceptReporters: false` にする。`true` にすると入力欄になり、
`startHats()` の照合（フィールドしか見ない）が効かなくなる。
メニューの値は数字の文字列なので、`startHats()` が値を大文字にする件
（お手本の `TERMINATOR_CHARS` のコメント）には当たらない。

**ハットの中では「1行読む」を使う前提**（書き起こしで提案し、打ち合わせで了承）。
読まれていない行がある限り起こし続けるので、中で「最新の行」だけを使うと、
行の列が減らずにずっと動き続ける（毎秒 30 回ほど）。
届いた行を順に 1 つずつ処理させたいので、この作りにした。

**1 行ずつ処理すると、1 秒に 30 行ほどが上限になる。** ハットは 1 回動くと、次に動けるのは
次の画面更新（約 33ms 後）。相手がそれより速く送ると、読みきれない行が溜まって表示が遅れていく
（実機で起きた、2026-10-13）。そのときは次のどれか。

- 相手の送信間隔を 50ms 以上にする（1 秒に 20 回以下）。余裕を見るなら 100ms
- ハットの中で「最新の行」を読んでから「受信データを捨てる」
- ハットを使わず、`ずっと` の中で「最新の行」を読む

上の 30 行という数字は Scratch の画面更新の間隔から出したもので、測ったものではない。

### 緑の旗と止めるボタンが点滅する

**「受け取ったとき」の下にブロックがあると、データが届くたびに緑の旗と止めるボタンが点滅する。**
Scratch の見え方として受け入れる（打ち合わせで決定、2026-10-13）。

緑の旗と止めるボタンは「スクリプトが 1 つでも動いているか」を表示している。
「受け取ったとき」は行が届くたびに一瞬動いて終わるので、その出入りがそのまま点滅に見える。
拡張機能の側から緑の旗の表示は変えられない。

実機で確かめた（2026-10-13）:

- 緑の旗のスクリプトが動き続けている間は、表示が「動いている」のまま変わらないので点滅しない
- 止めるボタンでそのスクリプトを終わらせると、点滅が見えるようになる
- 「受け取ったとき」の下のブロックを外すと、点滅は止まる

**点滅させたくないときは、「受け取ったとき」を使わず、`緑の旗が押されたとき` → `ずっと` の中で
「最新の行」を読む。** スクリプトが動き続けるので表示は変わらない。

## 7. モニター（ステージ表示のチェックボックス）

**この拡張機能の値ブロックには、チェックボックスが付かない。** 対策は要らない。

scratch-vm は、入力欄（はめ込み口）を持つ値ブロックにはチェックボックスを付けない
（`src/engine/runtime.js` の `context.inputList.length === 0` のときだけ `checkboxInFlyout`）。
この拡張機能の値ブロックは、どれも番号 `(1▼)` を入力欄として持つ。

当初は、お手本と同じく「モニターから呼ばれたら消さずに覗く」対策を入れる予定だった。
お手本の「1行読む」は引数を持たないためモニターになり、受信データを食べる問題が起きたが、
ここでは起きない。実装に取りかかってから気づいたので、ここを書き直した（2026-10-13）。

## 8. 将来の拡張（初版には入れない）

### 送信

初版は受信だけ。ただし、**後から送信のブロックを足せるよう、ポートは送受信どちらもできる形で開く**
（Web Serial の `open()` は向きを指定しないので、特別なことはしない）。

### ACK などのハンドシェイク

拡張機能には組み込まない。決まった手順を組み込むと、相手の機器もそれに合わせたプログラムで
なければ動かなくなり、汎用でなくなるため。

送信ブロックを足したら、利用者が送信と受信のブロックを組み合わせて作る。

- Scratch が「送って」と送ったときだけ値を返す（問い合わせ型）
- 開始したとき「だれ？」と送り、相手が名前を返す（どの機器が何番かを確かめる）

### 自動でつなぎ直す

「1. Web Serial API による制約」を参照。

## 9. ファイル構成

お手本の Xcratch 版にならう。ただしデスクトップ版が無いので、お手本より単純になる。

- 拡張本体を **このリポジトリの中に直接置く**。お手本のように scratch-vm 側から複製する
  手順（`sync-block.mjs`）は要らない
- `xcratch/` のような下位ディレクトリは作らず、**リポジトリの直下**に `package.json` を置く

```
package.json                                   バージョンと依存
scripts/rollup.config.mjs                      entry と本体を 1 枚の .mjs にまとめる
scripts/setup-dev.mjs                          scratch-vm へのリンクを張る（最初に一度）
scripts/publish-docs.mjs                       成果物を docs/ へ置く（ビルドのたびに自動）
src/gui/lib/libraries/extensions/entry/        一覧のカード（index.jsx / translations.json / 絵）
src/vm/extensions/block/index.js               ブロックの定義
src/vm/extensions/block/serialChannel.js       1 つの番号ぶんの通信と受信の溜め
src/vm/extension-support  -> scratch-vm        setup-dev が張るリンク（追跡しない）
src/vm/util               -> scratch-vm        setup-dev が張るリンク（追跡しない）
dist/                                          中間成果物（追跡しない）
docs/multiserial.mjs                           配るもの（GitHub Pages の公開元）
docs/multiserial.mjs.map
```

`ArgumentType` / `BlockType` / `Cast` は、お手本と同じく scratch-vm からリンクで借りる。
手元の scratch-vm は `D:\work\uiapduino-esm-test\scratch-vm`（お手本が今リンクしている場所）。

GitHub Pages の公開元は **main ブランチの `/docs`** に設定する（ユーザー作業）。

### バージョン

`package.json` の `version` を一覧のカードの説明の後ろに `(v0.1.0)` の形で出す（お手本と同じ）。
初版は `0.1.0`。

### 絵

一覧のカード（600x372）、カード左下の小さな絵（80x80）、ブロックの頭の絵が要る。

初版は仮の絵を作る（打ち合わせで決定）。差し替える絵があれば、それに替える。

⚠ 左のカテゴリ一覧のアイコン（`menuIconURI`）は **base64 の data URI で渡す。**
scratch-blocks はこれを `style.backgroundImage = 'url(' + iconURI + ')'` と引用符なしで
CSS に書く（`core/toolbox.js`）。rollup の image プラグインは SVG を空白や `'` を含む
読める形のまま埋め込むので、そのまま渡すと CSS が壊れて何も描かれない
（2026-10-13 に実機で白い丸だけになった）。`index.js` の `toBase64URI()` で直している。

## 修正履歴

### 2026-10-13 — 2 台目以降の開始を「次のクリックを待つ」にした

実機で 2 つのことが分かった。

- 1 回のクリックで出せるダイアログは 1 つだけ。緑の旗の下に「開始する」を 2 つ置いても、
  2 つ目のダイアログが出ない
- 「受け取ったとき」の中に「開始する」を置くと、クリックのたびにダイアログが出て使えなくなる

そこで次のように変えた（打ち合わせで決定）。

- ダイアログを出せなかった「開始する」は待ち、画面がクリックされたらダイアログを出す
- 受信中の番号で「開始する」が動いても何もしない
- 状態の文言「ブロックをクリックしてください」を「画面をクリックしてください」に変えた

ほかの案は、「1 台ごとにブロックをクリックしてもらう（作りを変えない）」と
「一度許可したポートを、ダイアログを出さずに空いている番号へ割り当てる」だった。
後者は、どの micro:bit が何番になるかを保証できない（シリアル番号が取れない）ので採らなかった。
